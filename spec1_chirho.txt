== PROJECT OVERVIEW: OpenOrphanageChirho ==

The OpenOrphanageChirho platform aims to provide orphanages and children's programs with tools to manage their operations, with an initial focus on child sponsorship and needs management. The system will be built with a Rust backend running on Cloudflare Workers and using Cloudflare D1 for data storage.

== API Design Principles ==

-   Use RESTful principles for all API endpoints.
-   Use HTTP verbs correctly (GET, POST, PUT, DELETE).
-   Accept and respond with JSON.
-   Implement clear API versioning in the path: `/api_chirho/v1_chirho/`.
-   Secure sensitive endpoints with JWT authentication and role-based authorization.

== Database (Cloudflare D1) ==

-   Generate D1 compatible SQL schema for all defined structs (`models_chirho.rs` in each module).
-   Ensure relationships are defined (foreign keys).
-   All database interaction functions should be in the respective `db_chirho.rs` files within each module.
-   Use SQL parameters to prevent SQL injection. `ctx.env.DB_CHIRHO.prepare("...").bind(...)`.

== Security Considerations ==

-   **Input Validation**: Rigorously validate all incoming data for type, format, length, and content.
-   **Authentication & Authorization**: Protect all endpoints appropriately.
    -   Sensitive data (child details, full orphanage details) should require authentication and appropriate roles.
-   **PII Protection**: Handle Personally Identifiable Information with extreme care. Follow data minimization principles. Define what data is encrypted at rest if necessary beyond D1's capabilities.
-   **OWASP Top 10**: Keep these principles in mind during development.
-   **Rate Limiting**: Consider basic rate limiting for public or sensitive endpoints (Cloudflare features can assist).

== Development Practices ==

-   **Rustdoc**: Generate comprehensive documentation comments for all public functions, structs, enums, and traits.
-   **Unit Tests**: Create basic unit tests for core business logic within each module (e.g., a test file `tests_chirho.rs` in each module). Focus on logic not directly tied to Worker request/response cycle initially.
-   **Configuration**: Manage configuration (e.g., JWT secrets, external API keys) using Cloudflare Worker secrets. Do not hardcode secrets.
-   **`wrangler.toml`**: Structure this file for development and production environments. Bindings for D1 database (e.g., `DB_CHIRHO`), KV stores, R2 buckets, and secrets should be defined here.
